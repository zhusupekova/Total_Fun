# Game_MiniApp

## Stage 1 (scene + physics sandbox)

Минимальный стенд на Three.js для отладки арены и мяча без сети.

- `index.html` + `src/main.js` — статичная арена, 4 игрока (один локальный, три бота), мяч с кастомной 2D-физикой.
- Управление: `W/S/A/D` — движение локального игрока по своей стороне; `Space` — пауза; `R` — сброс мяча.
- Коллизии: отражение от стен, от игроков, ограничение скорости, легкое затухание; мяч не прыгает, есть blob-тень.

Запуск локально (нужен любой статический сервер):

```bash
# пример с встроенным http.server
python3 -m http.server 8000
# затем открыть http://localhost:8000/ в браузере
```

Дальше (этапы 2–3): доработать визуал/ассеты, подключить сетевую логику и Telegram Mini Apps.

## Полный план MVP (3D PvP игра для Telegram Mini Apps)

Цель: рабочий MVP на 4 игроков в real-time, статичная 3D-локация (ринг), персонажи без вращения, мяч с плоской кастомной физикой, стабильный FPS в Telegram WebView.

### Этап 1 — Сцена и физика (текущий, закрывается максимально)
- Зафиксировать размеры ринга, зоны игроков (4 стороны), габариты ворот/целей, правила удара/потери очков.
- Подготовить черновые ассеты (low-poly ринг, борта, простой мяч) в Blender → glTF/GLB.
- Клиентский стенд Three.js: камера, свет, арена, 4 слота игроков, управление без вращения (движение по X/Z в своей полосе).
- Кастомная 2D-физика мяча: движение по плоскости, отражения от стен/углов и игроков, изменение скорости от силы удара, лёгкое затухание, blob-тень. Без движков.
- Ограничения: нет сети, простые материалы, без пост-эффектов. (Готово в текущем прототипе.)

### Этап 2 — Контент и визуал
- Blender: финальные low-poly модели 4 персонажей (единая база + цвет/аксессуары), мяч, ринг/борта в стилистике макетов.
- Экспорт ассетов в glTF/GLB, подключение в сцену Three.js вместо примитивов.
- Лёгкие тени/свет, цветовая палитра, базовые ховер-эффекты удара (без тяжёлых частиц).
- UI-оверлей: старт/рестарт, статус игроков, мобильное управление (виртуальный стик или 4 кнопки).
- Оптимизация под мобильный WebView: без тяжёлых шейдеров, ограниченный полигон-каунт.
- Папка `assets/` — ожидание файлов `arena.glb`, `player.glb`, `ball.glb`; при наличии они автоматически подхватываются вместо примитивов (см. `assets/README.md`).

### Этап 3 — Сеть и интеграция Telegram Mini Apps
- Сеть: WebSocket, server-authoritative.
  - Сервер (Node.js): симуляция мяча и столкновений, хранение позиций, рассылка снапшотов/ивентов.
  - Клиент: отправка ввода, получение состояния, интерполяция для плавности.
  - Поддержка комнаты на 4 игрока.
- Интеграция Telegram Mini Apps:
  - Инициализация через `telegram-web-app.js`, работа в мобильном WebView.
  - Авторизация/идентификация игрока по Telegram ID, отображение ников.
  - UI: подключение к комнате, статус пинга, старт/рестарт матча.
- Тестирование: прогон на мобильных (Android/iOS) внутри Telegram, проверка FPS и стабильности.

### Критерии готовности MVP
- Игра запускается внутри Telegram Mini Apps, 4 игрока подключаются к комнате.
- Персонажи двигаются по своим сторонам без вращения, управление на тач/клавиатуре.
- Мяч с плоской физикой: отражения, корректные скорости, стабильное поведение.
- Матч проходит без крашей и заметных лагов, FPS приемлемый на мобильных.

### Что вне MVP (отложено)
- Продвинутые анимации и VFX, частицы.
- Матчмейкинг/рейтинги/прогрессия.
- Кастомизация, скины, снаряжение.
- Сложный UI/UX, метагейм.

### Инструменты и стек
- 3D: Blender → glTF/GLB.
- Клиент: Three.js (WebGL), минимальные материалы, без пост-эффектов.
- Сеть: WebSocket, server-authoritative физика мяча.
- Среда: Telegram Mini Apps, mobile-first.

### Интеграция с текущим стеком (Next.js фронт + отдельный WS-сервер)
- Оставляем Next.js как фронтенд и оболочку Telegram Mini Apps; сцену грузим клиент-сайд (dynamic import, `ssr: false`), ассеты лежат в `public/`.
- Поднимаем отдельный Node/`ws` сервис для real-time (server-authoritative): хранит игроков комнаты, считает физику мяча, рассылает снапшоты/ивенты; деплой на любой обычный хост с TCP/WS.
- Клиент (Next) отправляет ввод, получает состояние, интерполирует; HUD/управление в вашем UI-ките.
- Telegram Mini Apps: подключаем `telegram-web-app.js`, берём user/id, передаём в WS для идентификации, показываем ники; для локальных тестов — туннель (ngrok/Cloudflare Tunnel) и запуск в WebView Telegram.

### Stage 1 — что показать заказчику (чек-лист)
- Запуск: локальный сервер (`python3 -m http.server 8000`), открыть `http://localhost:8000/`.
- Управление: `W/S/A/D`, пауза `Space`, сброс мяча `R`.
- Демонстрация:
  - 4 слота игроков, один управляемый, три бота.
  - Мяч скользит по плоскости, отражается от стен и игроков, меняет скорость, не подпрыгивает.
  - Персонажи движутся только по своим сторонам без вращения.
- Ожидаемое: стабильный FPS, предсказуемые отражения, тень под мячом. Никакой сети и тяжёлых эффектов на этом этапе.
